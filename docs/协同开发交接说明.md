更新：2026-10-08。当前：H01 首轮派发准备中；H02～H12 未开始。

用户本轮授权 Codex 向本机 ZCode、MiniMax Code、DeepSeek Harness 三个执行 Agent 派发开发，由 Codex 负责验收。本规则替代旧三方分工以及 2026-09-21 排除 DeepSeek Harness 的阶段规则。应用名称不代表实际模型；保留现有配置，不为派发更改模型或密钥。

## 需求与开发预期

StudyPilot 是业务系统；DeepSeek Harness 是独立、可替换的 Agent Runtime。业务专精通过 profile、context、tools、control 插件进入，不重写原 loop、工具调度、模型流、上下文压缩与恢复，不让旧固定 Planner 包住新 Runtime。

Java 提供可信身份、业务事实、权限、预算、确认、幂等与审计；Agent Service 拥有 Runtime、会话、模型配置及 Secret；Vue 通过同源 Agent API 接入。API Key 和模型地址不进入 Java 业务配置，Secret 不进入浏览器持久存储或事件日志。Harness 不直连业务数据库，不把开发终端能力开放给最终产品 Agent。

产品交互为全局悬浮球：左键打开 Harness 风格窗口，右键提供设置、新会话、历史及状态。保留自然判断、补查、追问与工具结果后的继续推理，避免关键词脚本或固定答复代替模型判断。旧 Agent 专属页面在新路径验收后迁移，保留业务页与历史数据。

原能力不被业务代码破坏是机制约束与评测目标，不能承诺任意回答完全相同。完整 Capability Manifest 基于真实接口编译；页面上下文仅提供定位提示，不能授予权限。先离线基线，H05 治理后才做真实 DeepSeek 成对评测。

设计：[接入设计](superpowers/specs/2026-10-08-studypilot-harness-integration-design.md)。执行：[H01～H12 计划](superpowers/plans/2026-10-08-studypilot-pluggable-harness-runtime.md)。历史：[旧交接全文](history/2026-10-08-协同开发交接说明-旧版.md)，仅供溯源，旧 push/merge/下一 Task 指令不自动生效。

## 执行与回执

1. 先读取本任务书、设计和计划，核对 `pwd`、分支与基线。应用当前 workspace 标签可能仍是 Task33，所有文件与命令必须使用本轮工作树。若应用沙箱无法访问，报告 BLOCKED，不改旧工作树或绕过权限。
2. 允许本轮离线测试、任务目录内编码和本地提交。不得 push、merge、deploy、改当前模型/密钥、操作真实用户数据、重启现有服务或做付费模型评测。不得删除或硬重置他人内容。
3. 业务代码与缺陷先 RED 再 GREEN；文档/清单做结构校验。禁止只验证 HTTP 200 就写端到端通过。记录 Mock/offline/local-client/provider/production 证据层级。
4. 回执状态仅用 ACKNOWLEDGED、IN_PROGRESS、READY_FOR_CODEX、BLOCKED；附实际 cwd、branch、baseline、commit、文件清单、测试命令/结果、限制与未覆盖项。未知实际 provider model ID 写未知，不通过额外调用探测。
5. 完成后本地提交并停止，等待 Codex。Codex 审查规格、diff、测试、失败路径及必要真实客户端证据；当前无授权推送合并或部署。用户认可后才推进下一 Task。
6. 每端证据写 `docs/verification/harness/h01-<agent>.md`，不抢写公共文档和知识库主档案。Codex 汇总 expected/actual、残余风险和下一门禁，并归档 Obsidian。
